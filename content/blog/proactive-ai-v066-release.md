## 一个藏在质量闭环里的洞

v0.6.5 给插件生成链路装上了三层质量保障：评审与自修复、写盘守卫、多轮试玩。其中「自评审」（`reviewPrompt`）允许插件作者把 schema 管不到的质量标准——数值是否合理、叙事是否出戏——写成评审提示，让引擎在输出后自动审查、不通过就带着结论重新生成。

但我们在复查时发现：**评审器自己的输出没有被约束**。

普通生成节点有完整的结构化管线：JSON Schema 注入 + JSON mode + 校验失败自动回喂重试。而评审器这条侧通道当初是手搓的轻量调用——schema 管线整个漏接了。后果是两种失败模式：

| 评审器的实际行为 | 此前发生什么 |
|---|---|
| 用自然语言回答（大概率） | 解析失败 → 按约定放行 → **评审静默失效，形同虚设** |
| 输出 JSON 但缺 `pass` 键 | 被判「不通过」→ 反复重生成 → **重试耗尽后误杀正常输出** |

## v0.6.6 的修复：同一条管线，同一个约束

现在评审器与生成节点共用 `generateWithRetry` 的结构化管线：

- **结论契约由引擎持有**：固定 schema `{pass: boolean, problems: string[]}` + JSON mode 强制，评审器最多两次尝试修正格式
- **评审隔离**：评审只看评审标准与被审输出，不加载会话历史与世界状态
- **fail-open 语义收敛**：评审器自身故障（网络/格式不合规）一律放行，不再误伤正常生成——但「故障」与「不通过」从此是两件被明确区分的事

净效果：插件作者写 `reviewPrompt` 只需要写**标准**，不需要操心输出格式；引擎内置的文件评审、修复器自评、需求评估评审、设定稿评审也全部收敛到这条被约束的管线上。

## 升级说明

这是引擎侧修复，无数据迁移。内置修仙世界维持 0.6.5 不变，已装 0.6.5 的用户升级后存档与进度不受影响。
