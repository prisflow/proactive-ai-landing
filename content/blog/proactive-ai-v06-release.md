## v0.6.0 是什么？

一句话：**Proactive AI 有了网页版，而且手机能用**。

之前 Proactive AI 只能坐在电脑前用。v0.6.0 加入了自建中继服务器：PC 宿主主动向中继出站注册一条 WebSocket 长连接，手机扫码打开网页版即可实时接续电脑上的对话——躺床上继续修仙、出门在外看剧情，都不用碰电脑。

## 它是怎么工作的

```mermaid
graph LR
    M[手机浏览器] -->|HTTP POST 发消息| R[中继服务器]
    R -->|WebSocket 转发| H[PC 宿主]
    H -->|WebSocket 推送| R
    R -->|SSE 订阅-推送| M
```

- **宿主出站注册**：PC 主动向中继发起 WebSocket 长连接（天然穿 NAT，无需端口暴露/公网 IP）
- **上行**：移动端消息经 HTTP POST 送达中继，转发给宿主进入同一套 agentLoop
- **下行**：宿主的事件（流式增量 / UI 消息 / 上下文切换）经 SSE 订阅实时推送到移动端
- **纯转发**：中继只做消息中转，零落盘——对话数据始终只存在于你自己的电脑上

网页版与 PC 端共用同一套渲染管线：Markdown、代码高亮、Mermaid 图表、插件推来的 UI 组件（按钮、状态面板、选项卡片），一个不少。

## 接入方式：链接或二维码

在设置页开启「公网中继」，填入中继地址与配对码，页面自动生成完整访问链接与二维码——手机扫码即进，无需输入任何内容。链接里的设备 ID 在 PC 端自动生成并持久化，配对码由你自己掌握。

## 安全设计

中继是公网入口，我们按「最小信任」设计：

- **双参校验**：每个请求都要答对「哪台电脑（device）+ 口令（code）」，答错任何一个都被拒绝；code 采用常量时间比较
- **限速**：认证失败按来源 IP 计数，超限临时封禁，防爆破
- **注册顶替防护**：同一设备重复注册必须携带一致的配对码，伪造即拒绝
- **资源上限**：WS 帧与请求体大小、设备数、单设备并发连接数全部封顶
- **源码不可经 HTTP 读出**：静态服务白名单扩展名，路径遍历与源码文件一律 404
- **离线感知**：宿主断开时网页版实时收到状态广播（状态点变灰、发送按钮复位），30 秒心跳覆盖崩溃等异常断开

## 升级与部署

- 桌面端：v0.5.x → v0.6.0 直接安装升级，数据无损（SQLite 本地库不变）
- 中继服务器：开源在 [prisflow/proactive-ai-relay](https://github.com/prisflow/proactive-ai-relay)，Docker 一键部署，Web UI 产物独立上传更新
- 手机端网页：开源在 [prisflow/proactive-ai-web](https://github.com/prisflow/proactive-ai-web)

PC 端聊天、修仙、插件，现在手机上也能继续了。
